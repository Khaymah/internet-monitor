### What changed in rc.8

Tested on a real WE router (Huawei HG630 V2, VDSL). rc.7 found the router and read the
line state, the internet session and the router's uptime, but not the line speed. rc.8
reads what that router actually offers:

- **Line speed (sync):** routers that leave it empty in the usual place (like the HG630
  V2) report it with the internet connection. The router card now shows it.
- **Why the last disconnect happened:** the router records the reason for the last
  drop. When it says the provider ended the session ("ISP disconnect") or stopped
  answering, the router card says so, the outage row in the report says "the provider
  ended the internet session", and "What your data says" counts those drops with a
  button to file a complaint.
- Actions a router doesn't support (like the traffic counters on the HG630 V2) are asked
  once and then skipped, instead of every minute.

### How to test

- [ ] With UPnP on, the router card shows "Line speed (sync)" after a minute.
- [ ] After the provider drops the connection (or after unplugging the phone line for a
      minute), the card shows "Last disconnect". The next day's report row for that
      outage says who ended it.

### Known limits

- The HG630 V2 doesn't offer its traffic counters or the line's SNR and attenuation over
  UPnP, so data-plan tracking isn't possible on it this way. Reading them from the
  router's own web page would need the router's password.
- The last-disconnect reason is the router's own record of the latest drop only; older
  drops are judged from the line and session state the app saw at the time.
